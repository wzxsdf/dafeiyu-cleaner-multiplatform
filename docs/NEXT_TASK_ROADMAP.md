## P0：发布前稳定性验收

### P0.1 真实安装回归

在本地加载 `dafeiyu-cleaner` 扩展，分别验证 Edge/Chrome：加载、刷新、禁用、启用、重新加载；同时打开 B 站和抖音确认平台名单、评论状态和统计互不串联；关闭并重开评论面板确认旧节点不会写入新页面；在两个标签页同时修改名单确认后台修订冲突不会覆盖更新。

已完成：Edge 抖音视频页 17 个评论/16 个扩展标记、隐藏与恢复、回复展开；B 站普通视频页滚动后 14 个扩展标记。待完成：工具栏、后台持久状态、双标签页和更多页面类型。

### P0.2 B 站回归矩阵

覆盖普通视频、分 P 视频、番剧评论区、个人主页、评论回复、手动隐藏/恢复、白名单、模型请求中切页和旧数据迁移。每个场景都需要真实页面结果；单元测试不能替代页面验收。

### P0.3 抖音回归矩阵

覆盖直接视频页、精选弹层、推荐流 A → B → A、回复展开、评论区重建、节点复用、缺少账号 ID、缺少评论 ID 和登录受限页面。已加载评论应能读取和标记；不支持场景需要显示明确的降级状态。

### P0.4 浏览器与文档收口

生成并检查 Chromium 发布目录；清理 README、隐私说明和进度文档中的旧行为描述；Firefox 需要单独打包和实测，不能把 Chromium 快照当作 Firefox 安装包。

## P1：识别评测基础设施

### P1.1 固化判定对象

分别标注账号是否由程序自动运营、单条文本是否可能由 AI 辅助生成、以及是否属于垃圾/广告/批量营销账号。本项目当前优先评测第一类。

### P1.2 建立平台独立样本

为 B 站和抖音建立去标识化样本，包含用户确认的自动运营账号、普通真人账号、AI 辅助真人发布账号、AI 话题/角色扮演/引用/否定/教程/短评论，以及明确自述自动发送或自动运营的正样本。每条样本保留平台、账号、页面、评论关系和标签来源；账号与页面必须同时隔离 split。

### P1.3 建立评测脚本

当前 `tools/evaluate-detection.cjs` 支持固定 JSON/JSONL、严格输入和来源校验、长 ID 保护、账号+页面 split 泄漏拒绝、策略源码哈希、3×3 矩阵、FPR、候选指标、拒判比例和错误样本。未知标签只用于观察，不进入准确率分母；构造 fixture 不能代替真实数据。

## P2：平台独立策略校准

### P2.1 B 站策略

对昵称、人设、等级、头像、作者身份、历史记录和评论文本做消融比较，校准强证据、疑似区间和证据不足区间，评估 DeepSeek 复核是否提供有效增量，不把模型分数当作概率。

### P2.2 抖音策略

先使用现有独立证据策略建立基线，重点评估普通短回复、作者评论、重复长评论、账号签名缺失和视频 AI 标签。只有样本证明有效后，才增加抖音特征或模型复核。

### P2.3 处理策略开关

在准确率达到预先约定的精确率门槛前，默认只标记，不自动隐藏；手动隐藏和白名单继续可用；模型输出只作为复核证据，不直接建立强身份结论。

## P3：架构收口与扩展准备

P0 稳定后继续拆分评论状态与 DOM 展示，补齐 `collectSnapshot()` 契约，为新平台适配器增加模板和契约测试，评估统一平台设置覆盖。目标是新增测试平台时只需注册适配器、清单和策略，不修改核心流程。

## P4：第三平台（可选）

P0～P2 完成前不接入第三个平台。之后可调研快手或 YouTube 的评论 DOM、稳定 ID、回复关系和权限边界，再决定是否实现最小闭环。

## 需要用户提供的资源

当前 P0 代码和自动化验证不需要新增资源。进入真实安装矩阵时，需要保持已连接浏览器并允许重新加载本地扩展。进入 P1/P2 准确率评测时，最好提供已确认的自动运营正样本及真人对照样本；没有这些样本仍可运行评测框架，但不能给出可信准确率结论。
